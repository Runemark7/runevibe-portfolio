# Postgres stays outside the cluster

The site reads PostgreSQL 18 on a separate VPS. The connection string comes only from `DATABASE_URL` in the environment or in a Kubernetes Secret named by the chart. Production requires `sslmode=require`. The application role is a member of the shared `apps` group and owns its database, because the API applies migrations on startup. The cluster is a single small node, so a database inside it would compete for RAM and would tie backups to the cluster. Local development uses the Postgres 18 service in docker-compose with `sslmode=disable`. That database is not production and holds no production credentials.
